# Changelog

Notable changes to this project. Format follows Keep a Changelog; versions
follow semantic versioning.

## [1.1.0] pending

### Changed, and it changes your results

**No iterate and no residual changes.** `PNL_REDUCTION_ACCUMULATORS` stays at 1
in this release, by decision 19 in `docs/DESIGN_DECISIONS.md`, so every value
this library computes is bit identical to the value release 1.0.0 computed, on
every backend and at every worker count. The reduction association change that
would move the last digits of every residual is release 1.2.0 work, where four
accumulators are measured as a variant rather than adopted as the default.

**Every timing changed, and none of it is drift.** A 1.1.0 second is not the same
quantity as a 1.0.0 second. Three things moved, each of them a defect this
release repairs rather than a tuning choice:

1. **The publication compiler.** Release 1.0.0 was measured with an unreleased
   GCC 16 trunk snapshot that nobody outside the development machine can
   install. Release 1.1.0 is measured with the released GCC 15.2.0, a stock
   Ubuntu package, at C++20. See decision 20.
2. **The Jacobi solver no longer copies the whole state every iteration.** The
   1.0.0 solver copied the full state on the calling thread once per iteration,
   serial work that no backend could divide and that the device path never
   performed, so it capped host Jacobi scaling and biased the whole CPU against
   GPU section. The solver flips buffers now. See `MEAS-01`.
3. **The timed region no longer contains the allocation.** The 1.0.0 timing
   enclosed a call that allocated three or four full state vectors on every
   repetition and first touched them serially, while the bandwidth it was
   divided by was first touched in parallel. The workspace is allocated once,
   outside the timing, and first touched by the backend that will use it. See
   `MEAS-10`.

Results from 1.0.0 and results from 1.1.0 are therefore comparable in what they
mean and are not the same measurement. The archived 1.0.0 generation ships beside
the new one under `experiments/results/archive/` with its own manifest and its
own README, so either generation can be reproduced or found to be
irreproducible. `docs/comparison_methodology.md` and the report both say so.

**The escape hatch, named here for the reader arriving from 1.2.0.**
`PNL_REDUCTION_ACCUMULATORS = 1` reproduces the 1.0.0 and the 1.1.0 values
exactly. It is the default in this release and it is a supported configuration,
not a debugging leftover.

### Added

- **An install and export API, which is why this is a minor bump and not a major
  one.** `install()`, `export()`, a generated `pnlConfig.cmake` and
  `pnlConfigVersion.cmake`, the namespaced `pnl::core` target, and a consumer
  preset. Release 1.0.0 shipped none of these, so **it exported no public API at
  all**: there was nothing a consumer could have compiled against and therefore
  nothing this release can break. A reader who sees the `SweepFunction` signature
  change and the new pure virtuals on `Problem` and `Backend` would otherwise
  reasonably ask why this is not 2.0.0, and the answer is that those types were
  never installable. From 1.1.0 onward the compatibility promise is real, because
  from 1.1.0 onward there is something to promise about; `CONTRIBUTING.md` states
  which headers are public, what the ABI position is for a mostly header library,
  and what a consumer may rely on.
- **`pnl/version.hpp`**, generated by CMake from the `project()` version, giving
  the version as three integers and as the string they spell. The first version
  this library has ever had that a consumer can query, with a unit test that the
  two spellings agree.
- **Registries for backends and solvers.** `make_backend` was a hard coded `if`
  chain and `all_solvers()` a fixed list. A backend registered from a foreign
  translation unit is constructible by name now, and `examples/custom_backend.cpp`
  is one.
- **`CMakePresets.json`** with `dev`, `dev-debug`, `asan-ubsan`, `tsan` and
  `consumer` configurations, so the sanitizer builds are one cache variable
  rather than a remembered flag string.
- **Two examples**, `examples/poisson.cpp` and `examples/custom_backend.cpp`,
  built by `make install-test` as a separate project against a staged install
  through `find_package(pnl)`.
- **A continuous integration matrix that proves what the badge claims.** GCC 14,
  GCC 15 and Clang 18 across Debug and Release with warnings as errors and the
  compiler asserted by name and major version; AddressSanitizer with
  UndefinedBehaviorSanitizer; ThreadSanitizer over the equivalence suite at 1, 2,
  4 and 8 workers; MPI at 1, 2 and 4 ranks plus the rank failure test; a CUDA job
  that compiles CUDA instead of skipping it; a job that asserts the optional
  backends really are absent when they are switched off; an install test; and a
  reports job that rebuilds both PDFs and compares their numeric tokens against
  the tracked copies. Every action pinned by commit SHA, with `dependabot.yml` to
  move the pins.
- **`scripts/migrate_summary.py` and a `--migrate` flag**, so that adding a column
  to the result schema no longer makes `make sweep` exit 2 against the committed
  summary and no longer forces a full re measurement to get the build back.
- **Eight result columns**: `sweeps`, `passes`,
  `dram_bytes_per_unknown_per_sweep`, `pinning_status`, `measured_at`,
  `seconds_reps`, `kernels` and `kernel_variant`. `seconds_reps` carries every
  repetition in run order, because three order statistics cannot be resampled and
  the knee is a bootstrap.
- **Spread and verdict machinery.** Every timing table carries a spread column,
  every timing figure carries whiskers, `report/tables/dispersion.tex` reports the
  dispersion of every block, and five verdict fragments state each comparison in
  the generator's own words, refusing to call an effect smaller than its own
  spread a result. The core knee is reported with a bootstrap interval and with
  the disagreement between backends stated as a result.
- **A non temporal store triad**, probed beside the plain one at a matched worker
  count, and both candidate byte models published side by side with the selection
  rule pre registered before the measurement and the outcome quoted from that
  registration.
- **Generated prose.** `report/tables/bandwidth_scaling.tex`,
  `report/tables/numbers.tex` and `report/tables/traffic_model.tex`, plus a
  generated region in `docs/comparison_methodology.md`, so a sentence asks the
  generator for a figure and a figure the generator cannot derive is a build
  error rather than a stale claim.
- **A related work section** in the discussion and `docs/RELATED_WORK.md`, naming
  the prior art for deterministic reduction and stating what this work adds
  beyond it.
- **A test suite that can reach the defects.** Property tests over the chunking
  and reduction partitions, twelve golden iterates diffed bit for bit, the
  boundary sizes and the rich right hand side in the equivalence suite, hybrid
  and pinning coverage that did not exist, a device contraction probe with its
  deliberately fused twin, three fuzz targets and a relative performance gate.
- **`CITATION.cff`**, an `SPDX-License-Identifier: MIT` line at the top of every
  source file, and a plain statement of how this repository was authored, in
  `CONTRIBUTING.md` and in the `notes` field of `CITATION.cff`.
- **A contribution process** in `CONTRIBUTING.md`: who reviews, who merges and how
  a disagreement is resolved, beside the technical rules that were already there.

### Known limitations

Carried into release 1.2.0:

- **Fortran.** The kernel provider, the `fortran_omp` and `fortran_dc` backends
  and the layout and aliasing contract across the boundary are part C, and none of
  it is in this release.
- **Assembly.** The hand written AVX2 kernels, the guard page harness and the
  measurement of four reduction accumulators as a variant are part D.
- **The container.** There is no Dockerfile, no Spack environment and no hash
  pinned `requirements.txt`, so the Python plotting set is still installed
  unpinned. Reproducing the figures needs the toolchain table in `PROGRESS.md`
  rather than an image.
- **No baseline.** Nothing here is compared against an existing library. The
  PETSc comparison, on the same stencil and the same machine, is 1.2.0.
- **`pcore` and `ecore` pinning cannot bind under WSL2.** The defect that let them
  claim a pinning they had not achieved is fixed and a request for either now
  fails loudly instead of silently pinning nothing, but the guest synthesises a
  homogeneous topology and the policies remain unusable here. No published row
  uses them.
- **The traffic model question is open.** The rule was fixed before the
  measurement and the outcome is unresolved: the statistic is 1.0242 and its
  interval, 0.7844 to 1.1304, contains the threshold. Settling it needs the
  assembly triad of part D, which measures the same quantity without the compiler
  choosing the store instruction.
- **The per pass byte model for the multi pass solvers.** The declared and counted
  columns bracket the traffic rather than measuring it: the declared model charges
  one sweep and is the lower bound, the counted model charges every pass a full
  stencil pass and is the upper bound, and the two conjugate gradient cells above
  one hundred percent mark a loose bound and not a kernel that beat its memory
  system. A count that charges a red black pass for the half it writes and
  conjugate gradient's inner products for the nothing they write would replace the
  bracket with a number. It is `MEAS-14`'s open item and decision 24.
- **No DOI and no deposit.** `CITATION.cff` carries no DOI field, by decision 22,
  because a DOI shaped string that resolves to nothing would be the only
  unverifiable claim in a repository whose argument is that every number traces to
  a run. `paper.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md` and the issue templates
  wait for a submission to actually be decided.

Standing since 1.0.0, and still true:

- The performance versus efficiency core split cannot be identified from inside
  WSL2; the knee is reported from the aggregate scaling curve instead.
- MPI ranks replicate the whole grid rather than allocating a local slab. The
  communication volume is unaffected; the memory ceiling is not.
- Iteration counts at the largest grids are extrapolated from verified closed form
  rates for the methods whose counts grow like n squared.
- Every device conclusion concerns bandwidth bound stencil work.

## [1.0.0] 2026-08-02

First release. Consolidates two earlier projects, a numerical methods library
and a parallel scientific computing study, into one repository whose organising
idea is that neither has alone: one numerical library, many execution backends,
so a benchmark can isolate what each programming model costs on identical work.

### Numerical core

- Root finding: bisection, Newton, Brent, each with its convergence order tested.
- Quadrature: adaptive Simpson, Gauss Legendre with nodes computed by Newton
  iteration on the Legendre recurrence rather than tabulated, and Romberg.
- Ordinary differential equations: classical RK4 and adaptive Dormand Prince
  5(4) with a standard step size controller.
- Dense linear algebra: LU with partial pivoting, Householder QR, and the Thomas
  algorithm for tridiagonal systems.
- Every result carries value, error estimate, iteration count, evaluation count,
  converged flag and an explicit stop reason, so a non convergence can never be
  read as success.

### Solver zoo

- Twelve iterative solvers presented as one splitting family: Richardson,
  Jacobi, forward, backward, symmetric and red black Gauss Seidel, SOR, SSOR,
  red black SOR, block Jacobi, block Gauss Seidel, and conjugate gradient.
- Two problem families: the 2D Poisson five point stencil with closed form
  theory, and seeded dense systems in diagonally dominant and symmetric positive
  definite flavours.
- Block methods solve their diagonal blocks exactly, by the Thomas algorithm for
  the stencil and by LU for dense systems.

### Execution backends

- Seven backends behind one interface: serial, OpenMP, POSIX threads,
  `std::jthread` pool, MPI, hybrid MPI with OpenMP, and CUDA.
- **Bit identical iterates** across every shared memory backend at every worker
  count, and between the GPU sweeps and the CPU. Asserted as exact equality by
  the equivalence suite, not as a tolerance.
- Natural ordering Gauss Seidel preserves exact sequential semantics on every
  backend, including across MPI ranks through a pipelined token chain.
- Communication time is measured separately for the distributed backends.

### Measurement

- Declarative sweep matrix with nine blocks, each stating the question it
  answers.
- Resumable sweep driver with atomic merge and a session manifest recording both
  devices' measured STREAM triad bandwidth and the toolchain versions.
- Every result row carries backend, worker count, pinning, seed and the commit
  hash stamped into the binary.
- Figures and tables generated from the summary alone, idempotently.

### Documentation

- Main report, debug report and personal report, all built by `make reports`.
- `docs/comparison_methodology.md` written for a reader who will try to misquote
  a speedup.
- Engineering log kept from the first command, with symptom, root cause, options,
  fix and verification for each entry.

### Verified against theory

- Jacobi spectral radius matches cos(pi h) to 1e-3 relative.
- Jacobi to Gauss Seidel iteration ratio is 2.00 within two percent.
- Young's optimal relaxation factor confirmed as a genuine minimum.
- Optimal SOR changes the growth order from O(n squared) to O(n).
- The five point stencil is second order accurate with error constant
  pi squared over 12.
- Red black ordering penalty measured at 2.6 percent more iterations.

### Known limitations

- The performance versus efficiency core split cannot be identified from inside
  WSL2; the knee is reported from the aggregate scaling curve instead.
- MPI ranks replicate the whole grid rather than allocating a local slab. The
  communication volume is unaffected; the memory ceiling is not.
- Iteration counts at the largest grids are extrapolated from verified closed
  form rates for the methods whose counts grow like n squared.
- Every device conclusion concerns bandwidth bound stencil work.
